# 실습별 안내

번호 = 강사 화면의 '실습 N' 배지 = `prompt-pack.md`의 블록 번호. 입력 문장은 팩 원문을 쓴다.
'완료 표시'는 폴더 전체에서 찾는다 (`자료/` 안에 생겼을 수도 있다). 단, `.claude/` · `수업코치/`(이 스킬 사본) 안의 예시 파일은 빼고 본다. oneline-copy 스킬만 `.claude/skills/oneline-copy/`에서 찾는다.

## 실습 폴더 준비
- **오전 폴더 `my-agent`**: 강사가 나눠 준 압축을 바탕화면에 풀면 생긴다. 안에 `자료/`(예시 제품 소개서 · 후기 · 인터뷰), `수업코치/`(이 스킬 사본), 프롬프트 팩
- 압축이 없으면 고르게 한다
  - 코치가 만들어 주기: 바탕화면에 `my-agent/자료/`를 만들고 `assets/sample/`의 세 파일을 한글 이름(`아침결_소개서.md` · `고객후기.md` · `고객인터뷰.md`)으로 복사 (먼저 묻는다). 내 자료가 있으면 `자료/`에 넣으라고 안내
  - 직접 만들기: 바탕화면에 `my-agent` 폴더, 그 안에 `자료` 폴더, 내 자료 넣기
- 만든 뒤에는 수강생이 직접 **Open folder…**로 `my-agent`를 열게 한다 (지금 세션이 다른 폴더면 새 세션에서)
- **오후 폴더 `marketing-agent`**: 강사가 나눠 준 스타터 키트 압축. 없으면 깃허브 릴리스의 키트 zip을 받는다: https://github.com/Jinbro98/jinbro-class/releases/latest/download/marketing-agent-starter-kit.zip . 수강생이 브라우저로 받아 더블클릭해 풀거나, 코치가 내려받아 바탕화면에 푼다 (먼저 묻는다). 코치가 풀 때 파일 이름에 한글이 있으니 맥은 `ditto -x -k <zip> <폴더>`, 윈도우는 `tar -xf <zip> -C <폴더>`를 쓴다 (맥 기본 `unzip`은 한글 이름이 깨진다)
- **내 자료 vs 예시 자료**: 처음에 한 번 묻는다. 내 자료가 없거나 오늘은 연습만 하고 싶으면 예시 제품 '아침결 그래놀라'(가상)로 진행. 예시는 실습 문장의 파일 이름을 그대로 쓰면 된다

## 오전 · 클로드코드 입문

### 1. 설치
- 개념: 클로드코드는 Claude 데스크톱 앱 안 Code 탭. 따로 설치할 것 없음. Pro 이상 구독 필요
- 직접 할 일: claude.ai/download에서 설치 → 로그인 → 왼쪽 위 **Code** 탭
- 대신 실행: 불가
- 완료 표시: 이 대화가 Code 탭에서 열려 있으면 완료
- 막히면: `app-guide.md` 설치 막힘 표

### 2. 첫 실행
- 개념: 폴더가 클로드의 작업대. 고른 폴더 안에서 읽고 쓴다
- 직접 할 일: 압축 풀기 → 입력창 아래 환경 **Local** → 폴더 버튼 → **Open folder…** → `my-agent` → 권한 모드 **Manual** 확인
- 대신 실행: 가능 (팩 2 문장은 폴더 목록 보기라 안전)
- 완료 표시: 지금 폴더에 `자료/`가 있음
- 막히면: 환경 선택이 안 보이면 이전 화면 구성. 폴더 버튼부터 누르면 됨

### 3. 수업 코치 설치
- 이 스킬로 대화하고 있다면 완료. 아직 다른 수강생을 돕는 중이면 팩 3 문장을 안내
- 완료 표시: `/` 목록에 jinbro-class가 보임

### 4. 첫 업무: 답 대신 파일
- 개념: 답하는 AI는 화면에 글만 남기고, 일하는 AI(에이전트)는 내 폴더에 파일을 남긴다. 생각 → 행동(도구) → 확인을 반복하는 게 에이전트 루프
- 준비: `자료/`에 소개서 (없으면 `assets/sample/` 예시 자료를 한글 이름으로 복사 제안)
- 직접 할 일: 허락 질문 읽고 허용 → 파인더 · 탐색기로 `제품요약.md` 열어 보기
- 대신 실행: 가능. 하지만 직접 보내기를 강하게 추천 (첫 허락 질문을 직접 보는 실습)
- 완료 표시: `제품요약.md`
- 완료 체크: 파일이 있고, 고객 · 강점 · 가격 같은 칸이 있다. 진행 중 지나간 `Read` → `Write` 줄을 봤는지 물어본다 (루프를 눈으로 본 것)
- 막히면: PDF가 안 읽히면 입력창에 끌어다 놓아 첨부. 웹사이트면 팩 4의 두 번째 문장
- 더 해 보기: `제품요약.md를 표로 바꿔 줘` / `이 요약에 빠진 정보 3개를 나한테 물어봐 줘`

### 5. 계획부터 받기 (Plan 모드)
- 개념: Plan 모드는 파일을 건드리지 않고 계획서만 보여 준다. 큰 일 · 처음 하는 일일수록 계획 먼저
- 준비: `제품요약.md` (없으면 따라잡기)
- 직접 할 일: 모드 버튼 → **Plan** (맥 Cmd + Shift + M · 윈도우 Ctrl + Shift + M) → 문장 보내기 → 계획에 한 줄 고치기 → 승인할 때 '하나씩 직접 승인'하는 쪽 → 승인 뒤 모드 버튼이 **Manual**인지 확인
- 대신 실행: 불가 (모드 전환과 승인이 실습)
- 완료 표시: `상세페이지_초안.md`
- 완료 체크: 계획을 한 번 고쳤는지 물어보고, 초안에 고객 후기 문장이 들어갔는지 본다
- 막히면: 모드 메뉴에 Plan이 없으면 앱 업데이트. 승인 선택지에 auto · 자동 수락이 붙은 쪽을 눌렀다면 모드 버튼을 Manual로 되돌리기
- 더 해 보기: Plan 모드에서 `이 초안을 모바일에서 읽기 좋게 고치는 계획만 세워 줘`

### 6. 컨텍스트 눈으로 보기 (새 세션)
- 개념: 컨텍스트는 클로드가 지금 아는 것 전부(대화 · 읽은 파일 · 규칙). 용량에 한계가 있고 세션이 끝나면 대화는 사라진다. 남길 건 파일로
- 준비: `자료/고객인터뷰.md` (내 자료면 긴 글 아무거나)
- 직접 할 일: `/context` 입력 → 저장 문장 보내기 → `/context` 다시 → **+ New** 새 세션에서 같은 폴더 열기 → "아까 뽑은 고객의 말 알려 줘"
- 대신 실행: 불가 (슬래시 명령과 새 세션이 실습)
- 완료 표시: `고객의말.md`
- 완료 체크: 새 세션이 이전 대화는 모르지만 파일을 찾아 답했는지 물어본다. 핵심 한 줄: "대화는 사라지고 파일은 남는다"
- 막히면: `/context` 대신 세션 정보의 Context 카드로 봐도 됨
- 더 해 보기: `/compact`를 한 번 쳐 보고, 요약 뒤에도 같은 일을 이어 가는지 보기

### 7. CLAUDE.md 규칙 한 장
- 개념: CLAUDE.md는 대화를 시작할 때마다 자동으로 읽는 업무 매뉴얼. 말투 · 파일 이름 · 하지 말 것부터. 짧을수록 잘 지킨다
- 준비: 없음
- 직접 할 일: 규칙 없이 `제품 소개 한 문단 써 줘`를 먼저 보내 답을 받아 두기 (8번 비교용)
- 고르게 하기: 팩 문장 그대로 쓰기 / 내 말투로 맞추기 (코치가 질문 두 개: "답은 어떤 말투가 좋으세요?", "절대 쓰면 안 되는 표현이 있나요?" → 답을 넣은 규칙 문장을 코드 블록으로 만들어 준다)
- 대신 실행: 가능 (규칙 문장 보내기는)
- 완료 표시: 폴더 맨 위 `CLAUDE.md`
- 완료 체크: 말투 · 파일 이름 · 하지 말 것 세 칸이 있다
- 더 해 보기: `이 규칙을 CLAUDE.md에 추가해 줘: 답 끝에 다음에 할 일 하나 제안`

### 8. 규칙 전후 비교 (새 세션)
- 개념: 프롬프트를 길게 쓴 게 아니라 규칙 파일이 생긴 것. 새 세션은 CLAUDE.md부터 읽고 시작한다
- 준비: `CLAUDE.md`
- 직접 할 일: **+ New** → 같은 폴더 → `제품 소개 한 문단 써 줘` → 7번의 답과 비교
- 대신 실행: 불가 (새 세션)
- 완료 표시: 파일로는 판단하기 어렵다. 날짜가 붙은 새 파일(예: `20261101_제품소개.md`)이 생겼으면 규칙이 먹은 신호. 수강생에게 차이 한 가지를 물어 확인
- 막히면: 차이가 없으면 새 세션에서 했는지, CLAUDE.md가 폴더 맨 위에 있는지 확인

### 9. 내 첫 스킬
- 개념: 스킬은 자주 시키는 일의 절차를 이름으로 부르는 것. `.claude/skills/<이름>/SKILL.md` 한 장. `/이름`으로 부르거나, 설명과 맞으면 클로드가 알아서 꺼내 쓴다
- 준비: `제품요약.md`
- 직접 할 일: 스킬 만드는 문장 보내기 → 새 세션(**+ New**)에서 `/` 입력 → 목록에서 oneline-copy
- 대신 실행: 만드는 문장은 가능. `/oneline-copy` 부르기는 직접
- 완료 표시: `.claude/skills/oneline-copy/SKILL.md`
- 완료 체크: SKILL.md 맨 위에 name · description이 있고, 절차에 '제품요약.md 먼저 읽기'가 있다
- 막히면: 목록에 안 보이면 새 세션에서 다시 `/`. 이름은 영어 소문자와 하이픈
- 더 해 보기: `oneline-copy 스킬에 '과장 표현 쓰지 않기' 단계를 추가해 줘` → 결과 말고 SKILL.md를 고치는 습관

### 10. 커넥터 연결해 보기
- 개념: MCP는 바깥 도구로 가는 표준 통로(멀티탭). 앱에서는 '커넥터'라고 부른다. 회사 자료는 어느 서버를 거치는지 보고 연결
- 직접 할 일: 입력창 옆 **+** → **커넥터 추가** (또는 사이드바 **Customize**) → 서비스 하나 → 로그인 · 권한 읽기
- 고르게 하기: 연결해 보기 / 목록만 보고 쓸 만한 것 하나 고르기 (이것도 완료)
- 대신 실행: 불가 (로그인). 연결된 뒤 서비스 문장은 가능
- 완료 표시: 수강생 답으로 확인
- 막히면: 회사 계정은 관리자가 막아 두었을 수 있음 → 개인 계정. 끊으려면 Customize에서 끄기

### 11. 플러그인 둘러보기
- 개념: 플러그인은 스킬 · 서브에이전트 · 훅 · 커넥터를 묶어 한 번에 설치하는 꾸러미
- 직접 할 일: 입력창 옆 **+** → **플러그인 추가** → 하나 골라 카드의 네 칸(무엇을 · 누가 · 안에 든 것 · 범위) 읽기
- 대신 실행: 불가
- 완료 표시: 수강생이 '안에 든 것'을 한 문장으로 말하면 완료
- 주의: 설치는 선택. 마케팅 스킬 묶음은 오후 키트에 이미 있으니 지금 받지 않아도 된다
- 막히면: 브라우저가 비어 보이면 앱 업데이트, 아니면 강사 화면 보기

### 12. 서브에이전트로 나눠 조사
- 개념: 서브에이전트는 자기 작업 기억을 따로 가진 동료. 나눠 맡기면 메인 대화에는 결과만 와서 가볍다
- 준비: 업종 정하기 (예시 제품이면 '그래놀라')
- 직접 할 일: 웹 검색 허락 질문이 뜨면 읽고 허용. 진행 화면에서 서브에이전트가 따로 일하는 것 보기
- 대신 실행: 가능
- 완료 표시: `경쟁조사.md`
- 완료 체크: 가격 · 강점 · 말투 · 우리와 다른 점 칸과 출처 주소가 있다. 웹 자료의 숫자 · 가격은 틀릴 수 있다고 한마디
- 더 해 보기: `경쟁조사.md를 보고 우리 제품이 이길 수 있는 틈 하나를 찾아 줘`

### 13. 오전 종합 실습 (새 세션 · Plan)
- 개념: 대화 기억 없이 파일 · 규칙 · 스킬만으로 일하기. 오후 마케팅 직원이 이 구조
- 준비: `제품요약.md` · `고객의말.md` · `경쟁조사.md` · oneline-copy 스킬. 빠진 게 있으면 따라잡기 또는 "있는 파일만 읽고"로 문장을 바꿔 준다
- 직접 할 일: **+ New** → my-agent → 모드 **Plan** → 문장 보내기 → 계획 확인 · 직접 승인
- 대신 실행: 불가 (새 세션 · Plan)
- 완료 표시: 최근에 생긴 게시물 파일 3개 (인스타 · instagram · 게시물 등이 들어간 이름)
- 완료 체크: ① 파일 3개 ② 고객이 쓴 말과 경쟁사와 다른 점이 들어감 ③ CLAUDE.md 규칙(말투 · 파일 이름 · 금지 표현)을 지킴. 세 개를 하나씩 짚어 준다

## 오후 · 마케팅 에이전트 만들기 (marketing-agent)

### 14. 스타터 키트 풀고 오전 폴더 합치기
- 개념: 마케팅 회사 구조 = 폴더 하나. CLAUDE.md(일하는 순서 5단계 · 승인 관문) · 제품별 폴더 · 마케팅 스킬 7개
- 직접 할 일: 키트 압축 풀기 → **+ New** → **Open folder…** → `marketing-agent` → 모드 **Manual** 확인. 다른 폴더를 읽어도 되냐고 물으면 허용
- 대신 실행: 가능 (단, 새 세션은 수강생이 열어야 한다)
- 완료 표시: `.claude/skills/`에 스킬 8개(키트 7개 + oneline-copy), `자료/`, CLAUDE.md '내 규칙' 칸에 오전 규칙
- 막히면: 옮기기가 꼬이면 그냥 marketing-agent로 진행해도 오후 실습엔 지장 없음. `.claude`가 안 보이면 맥 Cmd + Shift + . / 윈도우 보기 → 숨긴 항목

### 15. 입사 첫날 인터뷰 → PROFILE.md
- 개념: 직원 뽑기. 자료를 먼저 읽고 초안을 내민 뒤 빈칸만 묻는 인터뷰. 모르면 TBD, 사람이 확정
- 직접 할 일: 질문에 답하기. 손님이 실제로 하는 말을 그대로 적으면 카피가 좋아진다. 다 맞으면 `PROFILE.md 확정할게`
- 대신 실행: 문장 보내기는 가능. 인터뷰 답은 절대 대신 하지 않는다
- 완료 표시: `products/<제품>/PROFILE.md`, `docs/products.md`에 한 줄
- 완료 체크: 7칸(개요 · 고객 · 포지셔닝 · 경쟁 · 채널 · 언어 · 톤)이 다 있고, 고객이 쓰는 말이 들어 있다
- 막히면: 질문이 길어지면 `나머지는 TBD로 두고 PROFILE.md 초안 먼저 보여 줘`

### 16. 프로필 없이 vs 연결 후 (새 세션 · 빈 폴더)
- 개념: 같은 요청인데 결과가 다른 이유는 '내 제품을 아는가' 하나
- 직접 할 일: 바탕화면에 빈 폴더 만들기 → **+ New**에서 그 폴더 열고 카피 요청 → marketing-agent 세션에서 같은 요청 → 나란히 비교
- 대신 실행: 불가
- 완료 표시: 수강생이 차이 한 가지를 말하면 완료
- 막히면: 차이가 작으면 PROFILE.md에 고객이 쓰는 말이 비어 있는지 확인

### 17. 전략부터
- 개념: 콘텐츠보다 전략이 먼저. 전략 문서에는 네 칸(목표 · 채널 우선순위 · 실행 체크리스트 · 측정 기준). 구호만 있으면 실패
- 준비: PROFILE.md 확정
- 대신 실행: 가능
- 완료 표시: `products/<제품>/strategy/` 안의 문서
- 완료 체크: 네 칸이 다 있고, 체크리스트 항목마다 주기와 결과물 단위가 있다

### 18. 전략대로 콘텐츠
- 개념: 게시물 하나 = 파일 하나. 맨 위 세 줄(플랫폼 · 게시 시점 제안 · 대상) 아래 바로 붙일 본문
- 준비: strategy 문서
- 대신 실행: 가능
- 완료 표시: `products/<제품>/output/<날짜-주제>/` 안 파일 3개
- 완료 체크: 파일마다 맨 위 세 줄이 있고, PROFILE.md의 톤 · 금지 표현을 지켰다. 마지막에 '외부에 낼 최종 묶음'이라 확인을 물었는지 본다

### 19. 결정 기록
- 개념: decisions.md에 방향 결정을 한 줄씩, 최신이 맨 위. 다음 날의 직원이 어제를 기억하는 방법
- 대신 실행: 가능
- 완료 표시: `products/<제품>/decisions.md` 맨 위에 `- YYYY-MM-DD · 결정 · 근거` 줄
- 완료 체크: 기록할 게 없으면 "기록 없음"이라고 말하는 것도 정상

### 20. 승인 관문 시험
- 개념: 되돌릴 수 없는 일(게시 · 발송 · 삭제)은 먼저 묻거나 하지 않는다
- 직접 할 일: 팩 20 문장(게시해 달라는 요청)을 보낸다. 에이전트가 거절하고 사람이 게시한다고 안내하면 통과
- 대신 실행: 불가. 코치도 실제로 게시하지 않는다
- 완료 표시: 수강생 답 (거절했는지)

### 21. 검색 점검
- 개념: seo-audit 스킬로 내 사이트 한 페이지 점검. 사이트가 없으면 경쟁사 사이트로
- 대신 실행: 가능
- 완료 표시: 점검 결과 (답 또는 파일)
- 완료 체크: 제목 · 설명 문구 · 본문 구조 · 이미지 대체 문구와 고칠 순서가 있다

### 22. 다음 날, 새 세션에서 (새 세션)
- 개념: 말 한 줄이면 어제 하던 일부터. 읽는 순서: products.md → PROFILE.md → decisions.md → strategy/
- 직접 할 일: **+ New** → marketing-agent → 모드 **Manual** 확인 → 팩 22 문장
- 대신 실행: 불가 (새 세션)
- 완료 표시: `output/`에 새 폴더
- 막히면: CLAUDE.md 3단계 문장이 그대로인지, 제품 이름을 정확히 말했는지

### 23. 결과물 말고 지침 고치기
- 개념: 게시물만 고치면 그 글만 좋아진다. 지침(CLAUDE.md 내 규칙 · SKILL.md)을 고치면 다음부터 전부 좋아진다. 고친 뒤 `docs/test-scenario.md` 시험
- 대신 실행: 가능
- 완료 표시: CLAUDE.md '내 규칙' 칸에 새 줄
- 더 해 보기: `docs/test-scenario.md` 시험 1~3 돌리기

### 24. 두 번째 제품
- 개념: 직원은 그대로, 담당 구역(폴더)만 하나 더. 제품끼리 섞이지 않는다
- 대신 실행: 문장 보내기는 가능, 인터뷰 답은 수강생
- 완료 표시: `products/` 아래 제품 폴더 2개 이상
